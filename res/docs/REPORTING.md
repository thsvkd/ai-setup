# REPORTING

## 작업 보고 (기본)

모든 완료 보고는 이 셋을 갖춘다. 항목마다 ID(`C1`, `C2`, …)를 붙여 사용자가 번호로 지목할 수 있게 한다.

1. **무엇을 왜 바꿨는가** — 변경 파일 기준. 요청과 어떻게 이어지는지 한 줄.
2. **실행한 명령과 결과** — 명령 원문·종료 코드·핵심 로그를 그대로 붙인다. **통과·실패·건너뜀·미검증을 구분한다.** 건너뜀을 통과로 적지 않는다.
3. **남은 것** — 위험, 검증하지 못한 것, 사용자 결정이 필요한 것.

## 쓰는 방식

- 주니어에게 설명하듯 쓴다. 맥락을 모르는 사람이 읽고 다음 행동을 정할 수 있어야 한다.
- 확인한 사실과 추론을 섞지 않는다. 추론은 추론이라고 말한다.
- 실패를 숨기거나 완곡하게 쓰지 않는다. 실패는 실패로 적는다.

## 검수 보고서 (HTML)

작업이 커서 대화만으로 검수가 어려울 때만 만든다 — 기준: `<예: 수용 케이스 10개 초과, 또는 사용자가 요청했을 때>`

- 위치: `<채워 넣기>`
- 담는 것: 케이스별 통과 여부, 각 케이스의 증거(명령·출력), 미커버 케이스, 남은 위험.
- 증거는 요약하지 말고 원문을 접어서 넣는다. 요약된 증거는 증거가 아니다.
