# CODE_STYLE

## 기본

- 주변 코드처럼 쓴다. 기존 파일의 네이밍·구조·오류 처리 방식을 먼저 읽고 따른다. 스타일 개선은 요청받았을 때만 한다.
- 포매팅은 사람이 아니라 도구가 정한다: `<포매터·린터 명령>`
- 코드·주석·식별자는 `<언어>` 로 쓴다. 사용자에게 보이는 문자열은 예외로 `<언어>` 를 쓴다.

## 이름과 구조

- 이름은 무엇을 하는지 말한다. `data`, `tmp`, `handle` 처럼 아무것도 말하지 않는 이름을 피한다.
- 함수 하나는 한 가지 일을 한다. 이름에 "and" 가 들어가면 나눌 신호다.
- 값은 상수로 올린다. 경로·타임아웃·URL 을 코드 안에 흩어 놓지 않는다.

## 주석

- "무엇"이 아니라 "왜"를 쓴다. 코드가 이미 말하는 것을 반복하지 않는다.
- 우회·제약·놀라운 선택에는 이유를 남긴다. 그 줄이 나중에 지워지는 것을 막는 것은 주석뿐이다.
- 죽은 코드를 주석으로 남기지 않는다. 히스토리가 보관한다.
- 적절한 docstring 형식을 채택할 것.

## 오류

- 삼키지 않는다. 처리하거나, 문맥을 붙여 올린다.
- 메시지는 무엇이 실패했고 무엇을 하면 되는지 말한다.
- 되돌릴 수 없는 동작은 실패 시 아무것도 하지 않은 상태로 끝난다(fail-closed).

## 안전

- 시크릿을 하드코딩·출력·로그·커밋하지 않는다. 환경 변수나 시크릿 매니저 경로로 참조한다.
- 파괴적 동작(삭제·덮어쓰기)은 되돌릴 수단을 먼저 만든 뒤 실행한다.
- 사용자 설정은 덮어쓰지 않고 외과적으로 병합한다. 파싱할 수 없으면 멈춘다.

## 언어별

- `<언어>`: `<이 저장소만의 규칙. 없으면 이 절을 지운다>`
