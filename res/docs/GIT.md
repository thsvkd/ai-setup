# GIT

## 커밋 단위

- 논리적 변경 하나에 커밋 하나. 되돌릴 때 함께 되돌아가야 하는 것만 묶는다.
- 테스트와 구현은 같은 커밋에 넣는다.
- 지나가다 발견한 무관한 수정은 별도 커밋으로 분리한다.
- 커밋마다 스위트가 통과하는 상태를 유지한다.

## 메시지

`<type>(<scope>): <무엇을 왜 바꿨는지 한 줄>`

- type: `feat` / `fix` / `docs` / `test` / `refactor` / `chore`
- 제목은 명령형 현재형, 마침표 없이. 본문은 "무엇을"보다 "왜"를 쓴다 — 무엇은 diff 가 말한다.
- 이슈·PR 번호가 있으면 본문 끝에 붙인다.

## 브랜치

- `<기본 브랜치 이름>` 에 직접 커밋하지 않는다. 작업마다 브랜치를 딴다.
- 이름: `<type>/<짧은-설명>` (예: `fix/duplicate-install`)

## 머지

- 기본은 `<merge 또는 rebase — 이 저장소의 관례를 적는다>`.
- 충돌은 임의로 한쪽을 버리지 않는다. 양쪽 의도를 확인할 수 없으면 멈추고 보고한다.

## 되돌릴 수 없는 것

- `push`, force push, 태그·릴리스, 브랜치 삭제, `reset --hard` 는 사용자 승인 후에만 한다. 실행할 명령을 그대로 보여주고 승인을 요청한다.
- 히스토리를 바꾸기 전에 되돌릴 지점을 남긴다 — 백업 ref 또는 임시 브랜치.
